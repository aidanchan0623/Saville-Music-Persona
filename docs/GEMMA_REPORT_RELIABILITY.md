# Gemma report generation: investigation and correction

Tested locally on 3 October 2026 with Ollama and `gemma3:4b`.

## What was observed

An earlier real-history regeneration used fallback text with the generic reason `invalid_language_json`. The old implementation did not retain the specific validation rejection, so the exact condition from that original call cannot be recovered.

The model was reachable and installed. Twelve seeded replays and one unseeded replay of the old request completed and passed parsing; many generated short closing paragraphs that were silently replaced by deterministic text. This establishes that the connection was working and that an accepted response did not necessarily mean every displayed section was generated by Gemma. It is not a reliability benchmark.

Code inspection found avoidable rejection paths:

- The model generated six positional strings, including an age explanation the renderer discards. A number in that unused field could reject all the visible prose.
- Validation failures immediately replaced the full report, and different failures shared a generic reason.
- Short closing text could replace the generated body before fact validation, concealing the original unsupported claim from the validator.

In the corrected live test, one response exceeded the permitted text length. The single repair request produced a valid report. Numeric and unknown-artist regression tests verify that factual checks remain enforced.

## Changes

- Generate five named fields with a JSON schema; include that schema in the prompt.
- Keep Musical Age and its explanation deterministic. Omit release-year metrics and dates from the prose prompt.
- Use temperature zero and a larger bounded output budget.
- Allow one repair request inside the same ninety-second time budget.
- Validate displayed facts before replacing an undersized closing paragraph.
- Expose a reason code for missing fields, unsupported numbers/artists, length violations and token truncation. Log the code, not the prompt or listening history.
- Label the partial closing-paragraph fallback rather than claiming an entirely model-written report.
- Increment the report prompt version so previous cached text is not reused as the corrected result.

The separate Overview generator retains its own short time budget. Offline, timed-out and invalid report generations still have complete deterministic fallbacks.

## Why this approach

Ollama recommends supplying the JSON schema through `format`, including the schema in the prompt, and lowering temperature for reliable structured output: [Structured outputs documentation](https://docs.ollama.com/capabilities/structured-outputs).

The generation API exposes `done_reason` and token counts, allowing token-limit termination to be distinguished from ordinary completion: [Generate API](https://docs.ollama.com/api/generate).

## Verification

- Full backend suite: **229 tests passed**.
- Frontend production build: passed.
- Real-profile report generation: validated in the browser and confirmed through response provenance.
- Offline and malformed output, bounded retry, repeated rejection, numeric claims, unknown artists, and ignored age prose have automated coverage.

These checks demonstrate the corrected paths on this machine. They do not guarantee that every future model output will pass validation.
